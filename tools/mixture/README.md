# Mixture

A playground for how a Portfolio's allocation reads as a **Mix** (a 4×4 grid of Plan colours, always one of the 32 kept Mix cases) and how each Plan type's **Brick** looks. Terms are defined in the repo's [`GLOSSARY.md`](../../GLOSSARY.md).

```bash
npm install
npm run dev        # http://localhost:5173; the browser console logs which checkout it serves
npm test           # core logic: src/core
npm run typecheck
npm run check      # typecheck, tests, lint, glossary terms: what CI runs
npm run probe -- <file>  # a test file with console.log shown (vitest hides it by default)
npm run brick-stats -- --save before.json  # distinct Brick shapes per family/Slope; --compare before.json, --show mountain/half
npm run vendor:check     # vendored fnm-core matches block at its README hash (CI runs this too)
npm run bricks:pick      # picks every exported Plan type's Brick from its Strategy and writes src/core/pickedBricks.json (a minute or two)
npm run bricks:check     # reruns the pick and fails if pickedBricks.json differs (CI runs this too)
npm run bricks:export    # writes every stored Brick as a vector for Figma to brickVectors.json (git-ignored; about a second)
```

- `src/core/mix.ts`: `buildMix` turns Plan values into a Mix: it ranks the Plan colours by value, keeps up to 11, and draws the Mix case nearest their values (`nearestMixCase`).
- `src/core/mixCases.ts`: `mixCases` lists every Mix case, a 4×4 Mix cut into 1×1, 2×1, 2×2, 2×3 and 2×4 pieces, largest first in the left Side while it fits, then the right, the largest alone able to take the left Side and the top of the right, from 75% up, all but `DROPPED_CASES` (20 of the 52 with up to 11 colours); `MIX_CASES` numbers the 32 left 1 to 32, one colour per Mix case colour, as the page shows them, `nearestMixCase` picks the one with as many colours nearest a set of values, and `caseValues` draws random values that snap back to a case (the Playground's Mix case picker, `src/components/MixCasePicker.tsx`, loads them into a Portfolio); the Mix cases page (`#cases`, `src/components/MixCases.tsx`) draws them.
- `src/core/brick.ts`: `generateBrick` draws a Brick on the Brick grid (4×4 by default; 2×2, 8×8, 16×16, 4×6 and 8×12 on the Bricks tab) with the Pattern Builder's generator and its newest Reference set, vendored in `src/vendor/fnm-core` (see its README).
- `src/core/planTypes.ts`: the 38 Plan types every Plan is one of, seeded from `planTypes.json`: the 34 on the Bricks page in Figma, in its order, then Investment Call, หุ้นไทย, หุ้นต่างประเทศ and หุ้นกู้. Each has whether it's in draws; one of the 34 also has its Collection (`collections.json` lists the eight in the page's order) and its Strategy, and is exported: `exportedPlanTypes` gives those, Collection by Collection. An exported Plan type has no Brick in this file, since its Brick is picked from its Strategy; the four that are not exported each have a hand-set Brick. `drawPlanTypes` picks the ones in draws for a new Plan, the Plan's Draw button and a picked Mix case. The Bricks tab edits each type's name and Plan colour, shows an exported one's Collection, Strategy and picked Brick, and edits the Brick of one that is not exported; every Plan of that type follows.
- `src/core/pickedBricks.ts`: the Brick of each exported Plan type on the four square Brick grids (2×2, 4×4, 8×8, 16×16), stored in `pickedBricks.json` as generator settings and a seed with the largest Block and whether it meets the Initial Cost target exactly. `planTypeBrick` gives the settings any Plan type's Brick is drawn with on a Brick grid (the stored Brick for an exported one, a portrait Brick grid taking the square one of the same width; the hand-set Brick for the rest) and `planTypeBrickCells` draws it. The file is written by `npm run bricks:pick` and not edited by hand: to change a Brick, change the Strategy in `planTypes.json` and run the pick again.
- `src/core/brickVectors.ts`: `brickVectors` turns the stored Bricks into vectors for the Bricks page in Figma, 136 in all: one per exported Plan type, under its component set's name `Brick/<Plan type name>` in the page's order, and per square Brick grid, under the size (`2x2`, `4x4`, `8x8`, `16x16`; the variant `Size=<size>`). It only redraws what `pickedBricks.json` stores, so `npm run bricks:export` (`scripts/export-bricks.mjs`) writes them on demand to `brickVectors.json`, which is git-ignored, as `{ "frame": 24, "bricks": { "Brick/GMI": { "2x2": { "path", "bounds", "cells" }, "4x4": … } } }`, and fails when an exported Plan type has no stored Brick or two share a name.
  - `path`: the Brick's outline (`brickOutline`) as SVG path data, `M x y L x y … Z` with a point at every turn, in px from the top left of the 24×24 frame, so every point sits on a cell line (12, 6, 3 or 1.5 px apart). It is the edge of the filled cells taken together, with no line between Blocks: one closed loop around the Brick, clockwise, then one around each hole, the other way, so the non-zero and the even-odd fill rule fill the same cells (no stored Brick has a hole today, so each is one loop). Where two parts meet only at a corner, the loop passes through that point on its way into the other part and again on its way back; it does not close one loop per part.
  - `bounds`: the box the outline takes up on the frame, `x`, `y`, `width` and `height` in px.
  - `cells`: the Brick's cells, row 0 first, `#` filled and `.` empty. A vector read back from Figma matches when its fill covers the centre of every `#` cell and of no `.` cell, however Figma rewrote the path.
- `scripts/figma-bricks.mjs`: the write of the export to the Bricks page in Figma, which an agent does through the Figma MCP by the project skill `.claude/skills/bricks-to-figma` at the repo root. The script never talks to Figma: `inspect` and `write <1 to 4>` print the code of one Figma call (the call's data, then `scripts/figma-bricks-plugin.mjs`, the code that runs inside Figma), and `compare <after.json> [<before.json>]` holds what an `inspect` call returned against the export, and against the page before the write. A call matches the page to the export by name first and writes nothing on a problem. It writes the geometry of each `Brick` vector only: `Size=32x32` takes the 16×16 Brick, and a component set with a `Tile` (`TILE_SETS`) takes its Brick in the 18×18 box inside it. A read gives one digest per component set of what its five vectors draw (`describeVector`: the cells filled, the box and the corner points, however Figma rewrote the path), one of the page's nodes and one of their fills.
- `src/core/pickBricks.ts`: `pickBricks` runs the Pattern Builder's rule (`presetBricks` in the vendored core, see `docs/adr/0001` at the repo root) on one square Brick grid, passing the exported Plan types in the order of the Bricks page with their Plan Covers, and fails when a Strategy allows no Brick; `pickSummary` counts what the pick command prints. Only `scripts/pick-bricks.mjs` and the tests load it: the search is too slow for the browser.
- `src/core/strategy.ts`: a Plan type's Strategy: Investment Style, Risk (one level or a range) and Initial Cost (one of `INITIAL_COST_STEPS`), then Monthly Cost, Expected Return and Content Type where the plan picker shows them, and which of the values are guesses (`guesses`). A Strategy is changed in `planTypes.json`; `strategyLine` words it for the Bricks tab.
- `src/core/planCovers.ts`: each Plan type's Plan Cover (`planCovers.json`, 16×16 cells from Figma), `coverMatch` to score a Brick against it, and `closestBricks` to search seeds for the best ones. On the Bricks tab each card shows its Plan Cover and match, and for a Plan type that is not exported Closest Bricks lists picks to apply. Copy planTypes.json copies every Plan type in the file's format, to paste over `src/core/planTypes.json` as the new defaults.
- Plan colours come from neon `theme/tokens/colors.json`; the light theme from `theme.json`.
